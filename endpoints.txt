# Endpoints the SDK targets, checked against the pinned spec (.api-version) by
# scripts/check_spec_drift.py. This file lists the spec operations the SDK
# targets; the check validates it BOTH ways:
#   * every line must exist in the pinned spec (no removed/renamed/typo'd op);
#   * the set must equal the REST operations implemented in src/rest.rs, modulo
#     the one documented allowlist in check_spec_drift.py:
#       - NON_REST_TARGETS — targeted but reached without a REST helper call;
#         e.g. GET /ws and GET /stream (WebSocket upgrades, opened by the
#         ws and stream clients).
#
# There is no ahead-of-spec parking (ENG-8617). Every REST wrapper in src/rest.rs
# is listed here, and every line here exists in the pinned spec — so an operation
# the pinned spec does not define must not be wrapped at all. Wrap it once the
# spec version defining it is PUBLISHED and pinned, not before.
#
# So: add a line here whenever you add a REST wrapper for a spec operation, or
# the drift check fails. Format:
#   METHOD /path   (path placeholders match the spec, e.g. {market_id})
#
# Paths are the spec's bare spellings (EDR-006, ENG-18324): the REST base is
# `https://<host>/v1`, so `GET /orders` goes out as `/v1/orders` and is signed as
# `/orders`, the path the indexer verifies after the edge strips `/v1`. The five
# bridge operations keep their `/api/v1/...` spelling until a published spec tag
# declares their bare twins (ENG-18318 landed them in the monorepo spec, not yet
# in a nexus-exchange-api release); `/v1/api/v1/bridge/...` routes and verifies
# as `/api/v1/bridge/...` (ENG-17186's routing table).
